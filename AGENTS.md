# Repository Guidelines

## Project Structure & Module Organization
- CLI entry point `cmd/swiper/main.go` orchestrates the PDF pipeline and wires configuration.
- Reusable client code lives in `pkg/swiper`, exposing a stable API for embedding Swiper.
- `internal/` packages isolate concerns: `extractor` handles page decoding, `batch` orchestrates jobs, with `cache`, `pool`, `scanner`, and `metrics` providing shared services.
- Automation sits in `scripts/` (notably `scripts/ipp-enforce.sh`); evidence generated by gates belongs under `docs/evidence`, with run logs in `logs/ipp-gates`.
- Plans, changelog entries, and improvement artifacts are tracked in `docs/`, while local-only protocols remain in `docs/internal/protocols/`.

## Build, Test, and Development Commands
- `go mod tidy` keeps the module graph minimal before committing.
- `go build ./cmd/swiper` produces the CLI; `go run ./cmd/swiper -file sample.pdf` is the quickest smoke check.
- `go test ./...` runs unit suites, whereas `go test -race ./...` is mandatory for the TEST gate.
- `./verify-and-build.sh` performs dependency verification, runs tests when present, and emits an optimized binary.
- `./scripts/ipp-enforce.sh BUILD A04` applies the BUILD gate checks, including branch validation and formatting.

## Coding Style & Naming Conventions
- Follow Go defaults: tabs for indentation and `gofmt` output as the source of truth; run `go fmt ./...` before committing.
- Package names mirror their directories (e.g., `internal/pool`), and exported symbols in `pkg/swiper` should read cleanly as client API.
- Branch names follow `feature/aNN-description`; keep filenames snake_case and avoid introducing mixed casing in new assets.
- Configuration drafts under `docs/internal/...` are workstation-local—never add them to git.

## Testing Guidelines
- Co-locate tests with implementation (e.g., add `internal/extractor/extractor_test.go` beside the source).
- Prefer table-driven tests and keep fixtures under `testdata/`; document new fixtures when they affect other contributors.
- Capture race detector logs during the TEST gate and archive artifacts in `docs/evidence/IMPROVEMENT-*` for auditability.
- Record benchmark notes or integration evidence when touching high-throughput paths (extractor, pool, or cache packages).

## Commit & Pull Request Guidelines
- Commit messages follow `<type>: <description>` (e.g., `feat: add absolute path guard`) and reference the relevant improvement ID when applicable.
- Update `docs/CHANGELOG.md` for user-visible changes before running the VALID gate.
- PRs must link the tracked improvement, summarize gate evidence, and include a rollback plan; screenshots or CLI captures stay in the PR description.
- Run the SPEC→PROVE sequence via `scripts/ipp-enforce.sh` prior to requesting review, and attach the gate logs or evidence paths in the PR.
